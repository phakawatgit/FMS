Act as a Senior Backend Engineer. We are building the Backend API (`apps/api`) for our "First Aid & Medicine Management System (FMS)" using Express.js, TypeScript, PostgreSQL, and Prisma ORM.

Please implement a production-ready backend structure that handles database connectivity, error handling, and business logic transactions safely.

---

### Step 1: Database Connection & Health Check Module
1. **Prisma Client Singleton (`src/lib/prisma.ts`)**:
   - Create a singleton instance of `PrismaClient` to avoid multiple connection pools during hot-reloads.
   - Include graceful connection shutdown on `SIGINT` and `SIGTERM`.
2. **Server Entry Point (`src/index.ts`)**:
   - Ensure `dotenv` is configured properly to read `DATABASE_URL`.
   - Log explicit database status on server startup.
3. **Health Check Endpoint (`src/routes/health.ts`)**:
   - Route: `GET /api/health`
   - Test live DB connection using `prisma.$queryRaw\`SELECT 1\``.
   - Return HTTP 200 `{ status: "ok", db: "connected", timestamp }` on success, or HTTP 500 on failure with error details.

---

### Step 2: Global Error Handling Middleware (`src/middlewares/errorHandler.ts`)
1. Intercept **Prisma Known Request Errors**:
   - Code `P2002` (Unique constraint violation) -> Return HTTP 409 Conflict.
   - Code `P2025` (Record not found) -> Return HTTP 404 Not Found.
   - Code `P2003` (Foreign key constraint failed) -> Return HTTP 400 Bad Request.
2. Intercept **Zod Validation Errors** -> Return HTTP 400 with formatted error messages.
3. Intercept custom app errors (e.g., Insufficient stock) and fallback unhandled errors to HTTP 500 without crashing the Express process.

---

### Step 3: Visit & Medicine Dispensation API (Atomic Transaction)
Implement the core workflow for recording a patient visit and dispensing medicine (which must automatically deduct inventory).

1. **Zod Validation Schema (`src/validations/visit.schema.ts`)**:
   - Validate request body containing `patientId`, `nurseId`, `symptoms`, `diagnosis`, `treatmentNotes`, and an array of `dispensedItems` (each with `stockBatchId` and `quantity`).
2. **Controller & Transaction Logic (`src/controllers/visit.controller.ts`, `src/routes/visit.route.ts`)**:
   - Endpoint: `POST /api/visits`
   - Execute a `prisma.$transaction` to perform all database operations atomically:
     a. Verify every `StockBatch` in `dispensedItems` has sufficient quantity (`quantity >= requestedQuantity`). If not, abort transaction and throw "Insufficient stock" error.
     b. Create the `Visit` record.
     c. For each dispensed item:
        - Create a `Dispensation` record linking `Visit` and `StockBatch`.
        - Atomically decrement `quantity` in `StockBatch` (`quantity: { decrement: qty }`).
        - Create a `StockTransaction` audit log record (type: "DISPENSE", negative quantity).
3. Return HTTP 201 with the created Visit and linked Dispensation details.
